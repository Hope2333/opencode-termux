## 0. 结论摘要（TL;DR）

判据 = A（写入落 decoy）。**「env 免疫」不成立** —— 编译期固化命名只固化了
`app` 后缀，**不固化 XDG 根**。xdg-basedir@5.1.0 无条件读 env，固化后的 ELF
在诱饵 XDG_* 下同样被 re-root。

但**这不是回归**：现役 bash wrapper 用 `${XDG_DATA_HOME:-…}/opencode1`，同样
尊重外部 XDG_*。实测两者在诱饵下**逐字节相同** ⇒ 方案 A 与现役是**等价( parity)**
而非更强。文档原 §3.5 「比 wrapper 更宽容」的表述方向正确但结论需修正：
不是「A 更安全」，而是「A 与 wrapper 同样可被 env 覆盖」。

诱饵不被消费只在**一个**条件下成立：调用方不 export XDG_*（即 wrapper 场景）。
「xdg-basedir 在无 wrapper 场景不消费外部 XDG_*」——**此判据 B 不成立**。

副产物（重要）：发现 **tmp 根与现役不等价**，见 §5。

## 3. 实测 B — 固化命名后（app="opencode1/opencode"）是否仍被劫持
--------------------------------------------------------------------------------

重建整个 press5 管线成本过高（磁盘 99%，仅剩 18G）。改为**模块级等价实测**：

## 4. 关键对照 — 这不是回归，是等价（parity）
--------------------------------------------------------------------------------

现役 wrapper 的 export 算术（scripts/opencode1-launcher.sh:17-20）：

  export XDG_CONFIG_HOME="${XDG_CONFIG_HOME:-$HOME/.config}/opencode1"
  export XDG_DATA_HOME="${XDG_DATA_HOME:-$HOME/.local/share}/opencode1"
  export XDG_CACHE_HOME="${XDG_CACHE_HOME:-$HOME/.cache}/opencode1"
  export XDG_STATE_HOME="${XDG_STATE_HOME:-$HOME/.local/state}/opencode1"

⇒ wrapper 同样用 `${XDG_*:-$HOME/…}` 形式，**同样尊重外部预置 XDG_***。

### 4.1 现役 wrapper 端到端（$PREFIX 只读，假 HOME + 诱饵）

  $ head -c 60 $PREFIX/bin/opencode1   → #!/…/bash   (确为 wrapper)
  $ env -i HOME=$SB/home TMPDIR=$SB/tmp … XDG_*=decoy-* \
      $PREFIX/bin/opencode1 debug paths
  home       $SB/home
  data       $SB/decoy-data/opencode1/opencode      ← ★ decoy
  bin        $SB/decoy-cache/opencode1/opencode/bin
  log        $SB/decoy-data/opencode1/opencode/log
  repos      $SB/decoy-data/opencode1/opencode/repos
  cache      $SB/decoy-cache/opencode1/opencode
  config     $SB/decoy-config/opencode1/opencode
  state      $SB/decoy-state/opencode1/opencode
  tmp        $SB/tmp/opencode                       ← wrapper 下 tmp 不带命名空间

### 4.2 逐字节比较

  wrapper   : $SB/decoy-data/opencode1/opencode
  singleELF : $SB/decoy-data/opencode1/opencode
  => MATCH: patch is PARITY with wrapper even under adversarial XDG

**结论：方案 A 不引入新的 env 暴露面。** 现役包在诱饵 XDG 下与固化后的 ELF
落到同一路径。A 相对 wrapper 的真实增益是「绕不过去」（§6.1：没有第二个可执行
可直调），**不是**「env 免疫」。

## 5. 副产物 — tmp 根与现役【不等价】（文档 §3.5 需修正）

§3.5 声称「四个根 + tmp 全部成立」。实测**tmp 不成立**：

  场景                                 tmp 路径
  ------------------------------------ ------------------------------------
  现役 wrapper（app="opencode"）        $TMPDIR/opencode            ← 与 v2 共用
  固化后 ELF（app="opencode1/opencode"）$TMPDIR/opencode1/opencode  ← 不再共用
  v2（app="opencode"）                 $TMPDIR/opencode

原因：global.ts:15 的 `tmp = path.join(os.tmpdir(), app)` **同样 join 了 app**。
固化 app 顺带把 tmp 也 namespaces 化了。

影响评估：
- 方向上是**修复**而非回归 —— 它顺带关掉了 §6.3-2 记录的「$TMPDIR/opencode 跨代共用」
  这个既有共享面。
- 但它**改变了 tmp 落点**，属于行为变更，必须在 §5 断言清单里显式覆盖，不能默认
  「与 wrapper 逐字节相同」。
- 相关代码：`plugin/agent.ts:101`、`tool/shell/prompt.ts:280`、`agent/agent.ts:110`
  都用 `Global.Path.tmp`（含 permission 白名单 `path.join(Global.Path.tmp, "*")`）。
  路径整体下移一层，语义不变（仍是同一 app 的私有 tmp），但断言/文档需跟上。
- ⚠️ **既有测试会红**：`packages/core/test/global.test.ts:9`
  `expect(Global.Path.tmp).toBe(path.join(os.tmpdir(), "opencode"))`
  固化后此断言必然失败。重建前必须改测试，否则回归门会被这条挡住。

## 6. 等价性说明（为什么用未打补丁的 ELF + 模块级派生，而不是重建产物）
--------------------------------------------------------------------------------

用户任务允许在构建成本过高时改用现有裸静态 ELF 做等价实测。此处**两条证据链
互补**，须合并阅读，不可只看其一：

1. **实测链（真 ELF 端到端）**：用 press5 未打补丁的裸静态 ELF 跑 `debug paths`，
   证明 **XDG_* 确实被消费**（§2）。此结论**与 app 命名无关** —— 它只观测
   `xdg-basedir` 是否读 env，而 `xdg-basedir` 的读 env 行为发生在
   `global.ts:11-15` 之前、与 `app` 取值正交。
2. **推导链（模块级）**：用真实 xdg-basedir 模块 + 照抄的派生式，把 `app` 取值
   换成固化后的值，**直接计算** PATCHED 变体的落点（§3.1）。这回答了
   「命名固化后 XDG 是否仍被消费」——仍是 YES。

**差异必须写明**：实测链用的是**未固化命名**的 ELF，所以它落在
   `$SB/decoy-*/opencode`（无 opencode1 段）；固化后的 ELF 会落在
   `$SB/decoy-*/opencode1/opencode`（多一层）。**前缀差一层，XDG 消费行为完全相同。**
本文件 §4.2 用真 wrapper 补上了这一层的对照，证明「加不加这层，wrapper 与 ELF
都同样被 decoy 劫持」。

重建需先跑 patch 脚本 + 完整 bun 编译 + UPX）。留待发布决策后按 §7 迁移步骤执行。
