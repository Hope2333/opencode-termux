  Root cause: the 5 absolute-path files exist on disk but belong to NO
  package. They were deployed in place on Oct 2 by hand, not by pacman, so
  the -2 shell's DB row never covered them and nothing owns them:

    $ pacman -Qo bin/opencode                      -> error: No package owns bin/opencode
    $ pacman -Qo lib/opencode/runtime/opencode     -> error: No package owns lib/opencode/runtime/opencode
    (same for libopencode-crhandler.so and both pty .so files)

  pacman -U refuses to overwrite unowned files without an explicit
  --overwrite grant. NOTE: this is NOT the "Partition / is mounted read only"
  error the relative convention produced, and NOT a corrupt package — the
  transaction got as far as integrity+conflict checking and then declined.
  task-20 §4's sandbox rehearsal could not have caught this: a clean fakeroot
  has no pre-existing unowned files at those paths.

  Task-20 §4 predicted the reinstall would be "structurally sufficient"
  because the -3 package lays down 16 real files. That prediction assumed the
  target paths were empty. On oscar they are populated-but-unowned, so the
  conflict guard fires first.
