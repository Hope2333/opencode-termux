      实测无任何 O_WRONLY/O_RDWR 命中；且两代读到的 plugin 列表一致
      （v2 config 自带 8 个 plugin，v1 用其中 2 个的同名包）。
    - 做法：不动数据。把 ~/.opencode/ 登记为"两代共享只读插件清单"，
      在 v1 wrapper 加注释说明依赖关系；后续若 v2 改该文件，v1 插件集随之变。
    - 优点：零风险、零 v2 影响、不新增分叉维护。

  方案 C（彻底隔离，需 v2 短暂停顿）：把 project scope 也代际化
    - 前提：v1 无 env 可屏蔽 project scope，故只能靠 **cwd**——
      让 v1 不在 $HOME 下启动即不会命中 ~/.opencode/。
    - 做法：v1 wrapper 内 `cd` 到一个 v1 私有空目录再 exec。
    - 代价：改变 v1 启动 cwd（影响相对路径解析、git 上下文、项目级
      配置发现），属行为变更，风险中等；且 v2 若也在 $HOME 跑则不受影响。
    - 仅在用户明确要求"v1 绝不读任何 v2 名下文件"时才考虑。

  方案 D（结构性，需用户拍板）：把两代彻底分家
    - v2 迁到自己的 $HOME 下项目目录（如 ~/.opencode-v2/），或接受
      ~/.opencode/ 永久为 v2 专属、v1 通过方案 C 回避。
    - 超出本次诊断范围，涉及 v2 常驻服务重启，不建议在当前窗口做。

  建议：走方案 B（登记为共享只读契约），A5/A7 可独立放行。
