## S6 终局裁决（14:20Z）
- **E4 全量 strace（45s full trace, 129588 行）**: 无 seccomp 级静默失败（仅 madvise/rt_sigaction/memfd MFD_EXEC
  EINVAL 等良性项，无 pidfd/rseq/io_uring 故障）；trace 窗内 boot 仍活跃（models.dev connect t+28s），
  hang 过渡发生在窗口之后。首次尝试被 SIGKILL 于 UPX 解包期（疑似 LMKD 内存尖峰，MemAvailable 恢复 2.3GB 后重试成功）
- **warmup（warm cache 短路安装后）依然 hang** → **hang 与网络/安装无关，是容器切换引入的确定性 boot 死锁**；
  网络塌方（24KB/s）只是让 12min+ 的依赖自举掩盖了它
- hang 解剖学: 21 线程全 futex 空闲；主循环 0.4-1.4s 周期轮唤 7 个 worker（seq+4 空转）+128ms/1s 定时器；
  零 fork、零 socket、零文件 IO —— JS await 等一个永不到来的 worker 结果
- 卡点代码定位（2.0.12 bundle 未压缩段）: Effect-TS 分层服务 "@opencode/example/LocationServiceMap"，
  boot 流程 log "booting location services" 后逐 location contextEffect（concurrency unbounded），
  完成后才 log "location services booted"——今日该 await 永不完成
- **排除清单（实验证据链）**: runsv serve 进程（实验a 停服重跑仍冻结）/ config 与插件列表（E3 显式空数组、
  T9 noplug/mb）/ 二进制代次（press2+press3+anchor 三代同形）/ 磁盘·inode·内存·进程上限·设备重启 /
  sqlite-on-sdcard（python3 实测 0.07s）/ 主机连通性（github/npm/models curl 200）/ seccomp 系统调用失败（E4）
- **结论**: ~10:23Z 容器切换（files1 槽消失、runsv serve 启动）后的 oscar 容器态使 opencode boot 在
  LocationService 阶段确定性死锁（TUI 与 serve 同病），属容器级环境故障，非二进制/config/插件问题；
  **T10 无法在 oscar harness 上恢复全帧渲染，press3 输入轴验收因此 BLOCKED**（任何二进制级修复都无法
  在此环境验证——需容器侧恢复（files1 槽回归或容器重建回 5c 态）或 fork 源码级排查 LocationService 依赖的
