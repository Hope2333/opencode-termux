## 新发现：UPX×graft 不兼容（2.0.12 + bun 1.4.0 base）

本地旗舰与 oscar 均可复现，二分矩阵（rc：139=SEGV，132=SIGILL，0=PASS）：

| 变体 | ctor | UPX | 结果 |
|---|---|---|---|
| 未 graft 2.0.12-1 | — | yes | PASS（--version；但 TUI 崩=TLSDESC） |
| graft pristine | 全量回填 | no | PASS ×3 |
| graft pristine | 全量回填 | yes | **崩**（oscar 启动即崩 / 本地退出崩） |
| noctor（INIT_ARRAYSZ=0） | 关 | no | PASS |
| noctor | 关 | yes | **崩** |
| v3c（iterate，无回填） | 扫描 | yes | **崩** |
| v11（仅 key_create） | 半 | yes | **崩** |
| UPX -1 / --best / -4 | — | yes | 全崩（与压缩级别无关） |
| 提取文件换回旧 lib 内容（graged-upx 主件） | — | yes | **仍崩**（bun 未重提取，md5 不变） |

要点：崩因与 shim 逻辑无关（noctor 也崩）、与回填无关（v3c/v11 崩）、甚至与提取后
dlopen 的 .so 内容无关（换回旧 lib 内容仍崩）——崩因跟随「主 ELF 的 UPX 压缩产物」
本身（graft 只改了载荷里 6MB asset 字节）。CKT 取证（f2/local-ckt-grafted-upx.log）：
oscar pc=主 ELF 0x1e40294（LLINT 式跳转表取指 x26=0），本地 pc=0x26e9694 +
exit 路径 NULL 解引用（si_addr=0x11）。根因未钉死（疑似 UPX memfd 布局 × bun 固定
VA 区预留交互），留待后续专项。

**处置**：2.0.12-2 双包改载未压 graft runtime；oscar 上运行时以普通磁盘 ELF 运行，
shim ctor 正常回填（python ctypes dlopen 槽检 11/11 已验）。
